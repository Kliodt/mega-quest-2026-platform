# soundButtons — Sound Buttons

**Статус:** игра живёт вне платформы. Кнопки и звук — в аудитории; платформа показывает задание и ждёт.

Участники сканируют QR, слышат интро трека Канье Уэста «Runaway», который играл в актовом, и повторяют его кнопками в аудитории.

## Как устроено сейчас

- **Вопрос обычный.** Своих полей у типа нет: ни кнопок, ни последовательности бэкенд не хранит — только текст задания. Определение типа — одна строка.
- **Ответ засчитывает дрампад** (решение 2026-09-26). Железо в аудитории дёргает открытый `POST /pub/confirm_drum/:code` (в корне, без префикса `/api`), где `code` — номер пада: `0` → 3408, `1` → 3412, `2` → 4207, `3` → 4213, `4` → 4306. Номер лежит в самом вопросе (`externalAnswerCode` в `setup/questions/soundButtons.json`), по нему платформа находит аудиторию, команду с открытым вопросом и засчитывает ей ответ (`services/quest/confirmExternalAnswer.ts`). Про сами нажатия платформа по-прежнему ничего не знает.
- **Ожидание включает флаг вопроса** `waitsForExternalAnswer` (решение 2026-09-26): его ставят в `setup/questions/soundButtons.json`, а долгий запрос по нему заводит core, а не этот тип.
- **Фронт ждёт долгим запросом.** `GET /quest/state?since=<метка>` висит на сервере до четверти минуты и возвращается, как только состояние изменится (`services/openQuestion/waitForQuestionState.ts`, перечитывает раз в секунду). На фронте этим занимается хук `api/useQuestionStateWatch.ts`: получив изменение, он перечитывает прохождение, и экран сам уходит на следующий шаг. Опрашивать сервер вхолостую не приходится.
- **На экране только задание** и строка «Введите правильный ответ»: ответ набирается кнопками в аудитории, поля ввода у вопроса нет (`web/src/games/soundButtons/SoundButtonsContent.tsx`).
- **Неверных ответов нет:** `wrongAttemptPenaltySeconds` у вопроса нулевой.
- **Дальше:** появится сам механизм, который засчитывает ответ, — платформу под него менять не придётся, он просто пишет состояние.
