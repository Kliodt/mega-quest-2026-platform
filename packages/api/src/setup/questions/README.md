# Вопросы квеста

Вопросы квеста лежат здесь: **файл на тип игры**, внутри массив вопросов этого типа —
`history.json`, `blitz.json` и так далее. Один файл — один `gameType`, загрузчик это проверяет.

**В git этих файлов нет** (`.gitignore`): в них правильные ответы. На чистой копии репозитория
их кладут сюда руками.

Заливает их `npm run load-questions`: каждый вопрос пишется по своим аудиториям, код на дверь — по коду,
коллекции не пересоздаются. Остальные вопросы, команды и их прогресс загрузчик не трогает,
поэтому вопросы можно добавлять и править по одному хоть посреди квеста.

## Формат вопроса

**Вопрос описывается один раз и перечисляет свои аудитории** в `rooms`. Одна и та же игра стоит
в нескольких аудиториях слово в слово, а ответ берётся из маршрута команды, поэтому копировать
её по разу на аудиторию незачем. Маршруты команд ссылаются на вопросы именно аудиториями.

В одной аудитории при этом может стоять **несколько вариантов вопроса** — просто заведите их
соседними объектами с одной и той же аудиторией в `rooms`. При вводе кода ядро выдаст тот,
что дольше всего свободен, поэтому команды разойдутся по разным вариантам.

Коды на дверях здесь не задаются: они все лежат в таблице `../bindings.csv` (колонки
`code`, `room`, `location`) и заливаются своей командой `npm run load-bindings`.

Обязательные поля:

| Поле       | Значение                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| `gameType` | `SHAZAM`, `BLITZ`, `GOOGLE_FORMS`, `ENCYCLOPEDIA`, `HISTORY`, `TELEVISIONS`, `LIGHT`, `MINESWEEPER`, `SOCIAL_NETWORKS`, `SOUND_BUTTONS`, `STICKERS`, `YAGODNOE` |
| `rooms`    | аудитории вопроса: `{ "location", "roomNumber" }`, минимум одна          |

В аудитории: `location` — `lomo`, `cronva`, `birja`, `chaika`, `griva`; `roomNumber` — номер строкой.

Необязательные поля и их умолчания:

| Поле                         | Умолчание | Значение                                                     |
| ---------------------------- | --------- | ------------------------------------------------------------ |
| `html`                       | `""`      | текст задания, обычный текст тоже разметка                    |
| `acceptedAnswers`            | `[]`      | принимаемые ответы, каждый `{ "html": "..." }`                |
| `answerIsNextRoom`           | `false`   | ответ — номер следующей аудитории команды                     |
| `hasDynamicAnswer`           | `false`   | этот номер подставляет ядро по маршруту при открытии вопроса  |
| `shouldSendAnswer`           | `false`   | ответ уходит команде вместе с вопросом: механика игры прячет его сама |
| `waitsForExternalAnswer`     | `false`   | ответ засчитывает внешний механизм: экран команды ждёт его сам, поля ввода нет |
| `teamSlugs`                  | `[]`      | команды (их `slug` из `teams.csv`), которым достанется именно этот вариант; пусто — вариант общий и уходит по ротации. Команде выдаётся её вариант, а если его нет — общий; валидатор маршрута ругается, когда у команды в аудитории нет ни своего, ни общего |
| `cells`                      | `[]`      | коды клеток внутри задания (`{ "code", "row", "col" }`): их сканируют по ходу игры, к кодам на дверях отношения не имеют. Код клетки не повторяется, это проверяет загрузчик |
| `externalAnswerCode`         | `null`    | номер этого механизма: дрампад дёргает `POST /pub/confirm_drum/<номер>`. Только вместе с `waitsForExternalAnswer`, номер не повторяется |
| `wrongAttemptPenaltySeconds` | `0`       | штраф за неверную попытку                                     |
| `hints`                      | `[]`      | подсказки по порядку, каждая `{ "html": "...", "penaltySeconds": 60 }` |

Если на аудиторию вопроса нет кода в `bindings.csv`, вопрос в базу ляжет, но открыть его будет
нечем — загрузчик об этом предупредит.

Сочетания флагов ответа допустимы только эти три:

- оба сняты — обычный ответ, `acceptedAnswers` заполнены;
- `answerIsNextRoom` — ответ-аудитория известен заранее, `acceptedAnswers` заполнены;
- оба подняты — ответ-аудиторию подставляет ядро, `acceptedAnswers` пустые.

## Поля типов игр

Тип игры может требовать своих полей сверх базовых:

- `MINESWEEPER` — коды клеток `cells` теперь базовое поле вопроса (см. таблицу выше); размер поля знает фронт;
- `SOUND_BUTTONS` — `buttons` (`{ "html": "1", "toneHz": 261.63 }`) и `sequence` (индексы кнопок),
  ответ собирается из `sequence` при заливке;
- `BLITZ` — `quiz`: список `{ "html": "вопрос", "options": [{ "html": "вариант" }], "correctOption": 0 }`;
- `YAGODNOE` — `intro` (`{ "html": "вводная" }`) и `tableUrl`: ссылка на таблицу с анкетами участников,
  у каждого варианта своя. Само задание — в базовом `html`.
- `YANDEX` — `videoUrl`: ролик этой команды, файл лежит в `web/public/yandex_files/` под случайным именем.

Остальные типы своих полей не имеют — им хватает базовых.

## Пример

`light.json`:

```json
[
  {
    "gameType": "LIGHT",
    "rooms": [{ "location": "lomo", "roomNumber": "1216" }],
    "html": "Найдите на стене цитату и введите пропущенное слово.",
    "acceptedAnswers": [{ "html": "свет" }],
    "wrongAttemptPenaltySeconds": 30,
    "hints": [{ "html": "Смотрите над дверью.", "penaltySeconds": 60 }]
  }
]
```
